Packages, submodules and source documentation

The package directory links every workspace library and every packaged Git submodule, including its README and additional guides. Its JSON catalog reads package names, versions, exports, scripts and dependencies directly from the installed manifests. Repository links and commit IDs identify the checkout used for this build; local modifications are explicitly marked. The served documentation includes those modifications, which may not yet exist upstream.

Each component reference links to its owning package documentation. Read package limitations before choosing an API: the separate midi-ble barrel is incomplete, flodjs is a partial tracker port, and opendaw exports a scripting adapter rather than a DAWproject loader/saver. Working BLE adapters and DAWproject interchange live in audiobus. A listed prototype or package does not imply that all its intended features are implemented.

Build a preset from an intention

  1. Identify the players, their controllers, the musical source (live notes, a MIDI song, sequencer or generator), the intended transformations, and the sounds or external destinations. Determine whether players share one computer or connect separate computers through a room.
  2. Fetch index.json, find components by name or intention, and follow each entry's reference URL for its individual JSON documentation. For the complete reference in one request, fetch catalog.json. Filter by kind, description and guidance; copy exact, case-sensitive IDs. Inputs produce musical commands, transformers process them in order, outputs consume them, and audio effects process audio between output nodes. Instruments are another output factory.
  3. Prefer an existing published preset. Each directory entry's route has a preset.json containing its full page and workspace, including device IDs, options, routing and ordered steps. Inspect that JSON before overriding it.
  4. For a simple chain, use the versioned URL API below. For multiple parts, repeated device instances, instruments or audio effects, use the full setup format. Read the complete API reference for every parameter, replacement rule, encoding rule and limit.
  5. Look up each component's controls, defaults, requirements and configurationSource in the catalog. The source is served locally as plain text so an agent can inspect constructors, option interfaces, value conversions, GUI controls and special behavior. optionKeys is a source-derived discovery list, not a complete validated schema; inherited options and dynamically generated controls can add keys. Do not invent option names from display labels.
  6. Open the resulting setup, resolve any start-screen errors, start audio and test an actual input. Verify all intended output connections, transformer order, transport and MIDI part selection. For a room, verify connection status and tempo changes on a second participant. Deliver the link plus the remaining user actions.

The catalog is regenerated from this deployment's registries on each build. It includes disabled and registered components, hardware profiles shipped with the deployment, plugin variants and host-provided instruments. registered: false means metadata exists but the component is not in its corresponding factory: select a registered alternative. Runtime-discovered or externally registered components may extend the catalog after deployment; check the live pickers or exported workspace when that happens.

A transformer changes note/controller commands; an audio effect changes sound. For example, Note Reverb creates repeated notes while Reverb processes the instrument's audio. Output order matters for audio processing. A visual or text output need not produce audible sound; keep a synthesizer connected when sound is intended.

Simple shareable URL

Resolve the app root from this page's “Open Harmoneasy” link. Use that same deployment, including its base path. This example plays a computer keyboard through an octave transposition into Moog:

const appRoot = new URL("../../", documentationPageUrl); // docs/ai/ → app root
const url = new URL("parts/v1/", appRoot);
url.search = new URLSearchParams({
  inputs: "keyboard,onscreen-keyboard",
  outputs: "moog",
  transformers: "Transposer",
  bpm: "110",
  config: JSON.stringify({ steps: { "url-chain": { "0": { distance: 12 } } } })
}).toString();
console.log(url.href);

New shorthand devices have IDs url-input-<type> and url-output-<type>; a new chain is url-chain. In inherited presets, inspect actual IDs first. Lists append to existing sections by default; use inputs-mode=replace, outputs-mode=replace or transformers-mode=replace when replacing. Transformer indices refer to the final ordered list. Supplying midi to a new setup inserts a MIDI File Player when there is no MIDI File Player or Ensemble already present.

Full workspace: two independently playable parts

Full setups use page version 1 and workspace version 2. Transformer steps are an outer JSON string containing an array of JSON strings. Here two keyboards feed independent voices, and the upper voice passes through an audio delay. Supply the whole object as the setup query parameter:

const steps = (...configs) => JSON.stringify(configs.map(config => JSON.stringify(config)));
const setup = {
  format: "harmoneasy-preset", version: 1,
  name: "Two parts", description: "Live bass and delayed upper voice",
  clock: { bpm: 110, swing: 0, divisions: 24, bars: 4 },
  midiControls: { enabled: true, bindings: [] },
  workspace: {
    version: 2, activeChainId: "bass",
    devices: [
      { id: "keys", direction: "input", definition: { factory: "input", type: "keyboard" } },
      { id: "screen", direction: "input", definition: { factory: "input", type: "onscreen-keyboard" } },
      { id: "bass-synth", direction: "output", definition: { factory: "output", type: "moog" } },
      { id: "lead-synth", direction: "output", definition: { factory: "output", type: "moog" } },
      { id: "echo", direction: "output", definition: { factory: "output", type: "effect:delay", options: { time: 0.25, feedback: 0.3, mix: 0.25 } } }
    ],
    chains: [
      { id: "bass", options: { name: "Bass", active: true }, inputs: ["keys"], outputs: ["bass-synth"], transformers: steps({ type: "Transposer", distance: -12 }) },
      { id: "lead", options: { name: "Lead", active: true }, inputs: ["screen"], outputs: ["lead-synth", "echo"], transformers: steps({ type: "Transposer", distance: 12 }) }
    ]
  }
};
const url = new URL("parts/v1/", appRoot);
url.searchParams.set("setup", JSON.stringify(setup));

All IDs must be unique and connection references must resolve. Reuse one device across chains only when sharing that instance is intended. Do not include runtime objects (audio contexts, DOM elements, callbacks), credentials or temporary local file URLs. Each decoded setup and config has a 65,536-character limit; long setups can exceed browser or sharing-service URL limits sooner. Use the app's preset export/import or compressed room-sharing workflow for larger workspaces.

Worked intention: shared tempo and a group playing MIDI song parts

Intention: “Go to Harmoneasy, share tempo in a room, and let a whole group play parts from a MIDI file.” Use Ensemble for dividing a song into playable channel parts and Shared room for connecting separate computers. These are separate configuration steps.

  1. Inspect the any-song gamepad ensemble preset, or the Ode to Joy keyboard ensemble preset. The gamepad preset has no song selected: provide a reachable MIDI file URL or upload one after starting.
  2. Build the link below from that preset. The midi shortcut sets Ensemble's song while preserving its player and channel configuration. Do not combine Ensemble with the MIDI File Player-only track or playback shortcuts.
  3. Start the app. Load the song and inspect the resulting MIDI channels. In Ensemble, assign each player/source to one or more song channels, or use its automatic keyboard/gamepad part controls. MIDI channels are 1-based; file track indices are 0-based and are a different concept. Set the mode: Perform for expressive notes/chords with rhythmic companion parts, Assisted for activity-led playback, Together for quorum-based progression, or Conductor for a lead player's activity.
  4. For players at one computer, connect their keyboards/controllers/gamepads and test each assignment. For separate computers, open Shared room, start or join the named room, and distribute the actual invitation from that dialog. Follow any pairing/connection prompts. The host shares workspace, notes and tempo once connected. A room parameter supplies a room name; it does not itself prove that peers have connected.
  5. On each participant, enable audio and required inputs. Check Shared room status, test tempo propagation, and test that each player's events reach the intended Ensemble assignment. Controller/source IDs on different computers are not automatically interchangeable. Use the room's Classroom & jam roles when assigning melody, chords, bass or rhythm roles; these musical roles do not automatically map MIDI file channels.
  6. Start transport where needed. Verify each player can advance their assigned part, other parts behave according to the chosen Ensemble mode, and Stop releases all held notes. Share the final room invitation after setup and connection have been checked.
const url = new URL("presets/activities/ensemble-any-song-gamepads/parts/v1/", appRoot);
url.search = new URLSearchParams({
  midi: "midi/ode-to-joy.mid", // or an HTTPS URL returning MIDI bytes with CORS access
  bpm: "110",
  room: "group-rehearsal",
  config: JSON.stringify({ steps: {
    "ensemble-any-song-gamepads": { "0": {
      mode: "assisted", autoInputs: "gamepads", loop: true
    } }
  } })
}).toString();
console.log(url.href);

Open the shared-room ensemble starting point. This creates a starting configuration; player assignments and actual room connection must still be verified. See Ensemble's complete controls, defaults and source for players: [{ source, channels }], automatic inputs, assistance and timing options. Remote MIDI URLs must return actual MIDI bytes and permit cross-origin browser access. A file upload is local until distributed through a supported sharing flow or hosted at a stable URL.
